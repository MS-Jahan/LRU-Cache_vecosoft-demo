## 2. Core Implementation Requirements (`lru_cache/cache.py`)

### Data Structures

* Use a **Hash Map** (`dict`) for $O(1)$ key-to-node lookups.
* Use a **Doubly Linked List** with dummy `head` and `tail` nodes for $O(1)$ node removals, insertions, and reordering.
* Do not use high-level abstractions like `collections.OrderedDict` or `functools.lru_cache`. Build the custom Doubly Linked List from scratch to prove data structure mastery.

### Functionality & APIs

1. `Cache(capacity: int)`:
* Raise `ValueError` if `capacity <= 0`.


2. `get(key: Any) -> Any`:
* Return the stored value if present and unexpired; otherwise return `-1`.
* A successful read moves the node to the most recently used (MRU) position (immediately behind the dummy `head`).


3. `put(key: Any, value: Any, ttl: Optional[float] = None) -> None`:
* Insert or update the key-value pair.
* If key exists, update value/TTL and mark as MRU.
* If key is new and size exceeds capacity, evict the least recently used node (immediately before dummy `tail`) and delete it from the dictionary.


4. **TTL / Expiration Mechanism (Bonus Feature):**
* Support an optional `ttl` parameter (in seconds) in `put()`.
* Implement **lazy expiration**: check expiration during `get()` and `put()` operations. If expired, remove the entry from both the list and the hash map and return `-1`.



### Coding Standards

* Write strictly formatted Python 3.10+ code.
* Use explicit type hints (`typing` module / standard types).
* All docstrings and code comments must be written in clear English.
* Keep classes modular: define `ListNode` and `LRUCache`.
